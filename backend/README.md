# Сервер «Догляд»

Go 1.24 і SQLite у режимі WAL. PostgreSQL та Docker не потрібні: базу сервер створює сам під час першого запуску.

## Запуск

```powershell
cd backend
go run ./cmd/api
```

Демонстраційні дані в окремому файлі бази:

```powershell
go run ./cmd/seed
$env:DATABASE_PATH='./data/demo.db'
go run ./cmd/api
```

Ключі Web Push:

```powershell
go run ./cmd/keys
```

## Перевірка

```powershell
go test ./...
go vet ./...
gofmt -l ./cmd ./internal
```

## Три правила, які легко порушити

**Одне з'єднання з базою.** Пул навмисно обмежений одним з'єднанням: SQLite має лише одного письменника, і послідовні запити прибирають клас помилок «database is locked». Через це **не можна виконувати запит усередині циклу за незакритим курсором** — це заблокує сервер назавжди. Спершу зчитайте рядки у зріз, закрийте курсор, потім працюйте з даними. Регресійний тест `TestSchedulerDoesNotBlockSingleConnection` перевіряє саме це.

**Помилки не глушаться.** Кожна помилка бази або мережі має або потрапити в журнал через `s.logError`, або повернутися користувачеві зрозумілим текстом українською. Мовчазний `_ = rows.Scan(...)` колись приховав те, що екран підопічного повертав порожні поля. `s.logError` робить один виняток: скасований контекст (штатна зупинка сервера або від'єднання клієнта) пишеться як INFO, інакше журнал після кожного перезапуску повний «помилок» і справжню поломку в ньому не знайти.

**Час — за годинником підопічного.** Будь-який час, який бачить людина — у тексті сповіщення, у звіті, на екрані, — показується в часовому поясі підопічного через `s.wardLocation`. Сервер може стояти в UTC, помічник — у третій країні; діють усі за годинником того, кого доглядають. Регресійні тести: `TestReminderShowsWardLocalTime`, `TestAdaptationSignalsUseWardDate`.

## Схема бази

Єдине джерело правди — `internal/store/migrations/001_initial.sql`. Файл вбудовано у бінарник і застосовується під час запуску. Усі часові значення зберігаються у UTC у форматі RFC3339; локальний час підопічного обчислюється з його часового поясу.
